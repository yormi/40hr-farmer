02Sequences

Every ManyChat External Request must get an HTTP 200 with an empty body immediately. Slow work happens after that.

Inbound message

  Lead->>IG: types a DM
  IG->>MC: Default Reply
  MC->>S: POST /ig-inbound
  S-->>MC: 200 empty immediately

    opt current step needs parsing

      C-->>S: JSON status

    S->>MC: sendContent message 1
    S->>MC: sendContent later messages, buttons on the last

  else not on the list or no conversation
    Note over S: ignore the DM, save nothing
  end

The first event is slightly different: commenting PROFIT runs the comment flow, which POSTs trigger: profit_comment. ManyChat sends no message. The server starts the conversation and sends the welcome. A conversation existing on the server is what makes a lead active.

Quick-reply tap

Including “Talk to Guillaume.” It is a callback, not a ManyChat node jump. We do not rely on Default Reply to catch bare taps.

Handoff

  S->>MC: sendContent holding message

The server never sends again while human_handoff is true. Phil or Guillaume clears it with an admin endpoint (or the mirrored ManyChat field). Native Instagram-app replies have no 24-hour limit; the 24-hour window applies only to API sends.

03Pacing

Messages are never batched into one sendContent. Each line is its own call, spaced to match reading time. All of this runs after the 200 response, so delays do not count against ManyChat’s 10-second timeout. If the lead writes again mid-sequence, remaining queued messages for that contact are cancelled.

sequenceDiagram
  participant Lead
  participant S as Server
  participant MC as ManyChat
  Note over S: 200 already returned
  Note over S: thinking delay about 1 to 2 seconds
  S->>MC: sendContent message 1
  Note over S: delay from length of message 1, 1.2 to 4 seconds
  S->>MC: sendContent message 2 plus quick replies

Default delay rule

delay_ms = clamp(800 + 40 ms × characters in the previous message, 1200, 4000). The first reply after the lead speaks uses a short thinking delay (thinking_ms, default 1500). A say item may set delay_ms to override. Tree-level config.pacing sets base_ms, per_char_ms, min_ms, max_ms, and thinking_ms. Quick replies attach to the last message only. A typing indicator between messages should be sent if the ManyChat API supports it for Instagram — verify, do not assume it works.

04ManyChat — three thin pieces

No copy, no branching, no handoff flow, and no sendFlow. Live Chat is history only.

1

PROFIT comment trigger

POSTs the first event to /ig-inbound with trigger: profit_comment, plus contact id and Instagram handle. Sends no message itself.

2

Default Reply

No condition. Forwards {contact_id, ig_username, text} from every DM to /ig-inbound. The server ignores contacts with no conversation and saves nothing for them. Settings: trigger every time (not once per 24 hours, which would drop later replies) and skip story replies on.

3

Live Chat

Conversation history only. It does not trigger handoff and is not driven by a ManyChat flow. Phil replies in the Instagram app.

Decided: Guillaume’s existing Linode. Cloudflare Workers stay a possible later fallback, not the v1 plan.

🖥️

Linode

  • HTTPS via Caddy with Let’s Encrypt, on the Linode hostname 172-105-6-173.ip.linodeusercontent.com. Caddy proxies only /ig-inbound; everything else returns 404.
  • Test allowlist: ALLOWED_USERNAMES lists the Instagram handles the server answers. Anyone else is ignored. An empty list blocks everyone.
  • Deploy: chat-test/deploy.sh installs Node and Caddy once, then syncs code, secrets and the plan and restarts the service.
  • Process manager: systemd or pm2, so the app restarts if it dies.
  • Uptime monitor (for example UptimeRobot) on the inbound endpoint.
  • 10-second ManyChat timeout: reply 200 immediately, then run Claude and the paced sendContent sequence in the background (delays do not count against the timeout).
  • Database backups on a schedule.
  • Secrets (API keys, Slack webhook, request secret) live in environment variables, not in the repo.
  • Verify ManyChat requests with a shared secret header, so strangers cannot POST to /ig-inbound.

08Decision-tree language

One JSON file is the conversation. The editor draws edges from next / on_fail / else / branches / options, so the picture cannot disagree with the logic. Claude returns JSON only: ok + value, retry + followup, or intent: human. The server re-validates type and range.

ask, choiceWait — send a prompt, stop until the lead answers
message, condition, set, actionAuto-advance — run and continue immediately
handoff, endStop — holding message + Slack, or a recorded outcome. Both end the conversation on the server.

Also in the language

Templates use {{var}}. Conditions are a small safe expression subset, e.g. country in ["US","CA"] and english_speaker == true. Global intents: human and stop, from any node. Versioning via dsl_version, tree.version, and redirects. A null constant that the tree references blocks publish.

09Constraints

ConstraintHandling
24-hour window (API only)Server sends via the API only within 24 hours of the lead’s last message. Native Instagram-app replies have no 24h limit. Live Chat after 24h would need the 7-day Human Agent tag; the intended human path is the Instagram app.
Duplicate or out-of-order eventsv1 processes events as they arrive (no dedup, no per-contact queue). A duplicate can repeat a step; an out-of-order reply can hit the wrong question. Design for this is later.
Quick repliesMax 13 per message, captions about 20 characters. They disappear once the lead types or taps. Typed text still arrives via Default Reply; the server ignores contacts with no conversation.
